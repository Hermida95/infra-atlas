Code can be swapped for the previous version in seconds. A schema change cannot: the old code may not understand the new column, and everything written since the change is already in the new shape.

The way out is to make every migration backwards compatible for one release. Add the column, deploy code that writes both, backfill, deploy code that reads the new one, and only then drop the old one. Four boring deploys instead of one exciting one, and a safe rollback at every step.
