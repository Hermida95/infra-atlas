Two caches matter. The dependency cache keys on the lockfile, so a run that changes no dependencies downloads nothing. The layer cache lets an image build reuse everything above the first instruction whose inputs changed.

The trade-off is correctness. A cache keyed too loosely serves yesterday's bytes and hides a broken build, and a poisoned cache ends up inside a published image. That is why the job that builds what gets signed in this repo runs with caching turned off.
