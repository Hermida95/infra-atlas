Instance store is NVMe physically attached to the host the instance runs on. It is the fastest
storage available on EC2 -- millions of IOPS on the `i` family, with no network in the path --
and it is included in the instance price rather than billed separately.

It is also **ephemeral**, and the exact rule matters because it is a favourite exam detail: the
data survives a **reboot**, and is lost on **stop**, **hibernate**, **termination** or a **host
failure**. Stopping moves the instance to different hardware; the disks do not come with it.

So the design rule is simple: anything you would miss goes on EBS or S3, and instance store is
for things that can be rebuilt. Scratch space, temporary files, shuffle data in a Spark job, a
local cache in front of a database, buffer and index files a node rebuilds on startup. The
distributed data stores that use it well -- Cassandra, Kafka, Elasticsearch -- do so because
they already keep replicas on other nodes, so losing one node's disk is a rebuild rather than a
loss.

Two notes. The volumes must usually be formatted and mounted on first boot, typically in user
data, because they arrive raw. And they are encrypted with a key on the host that AWS manages;
you cannot bring your own, which occasionally matters for compliance.
