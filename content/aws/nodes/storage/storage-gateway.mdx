Storage Gateway is a virtual appliance that runs in your data centre (or as a hardware box, or
on EC2) and presents a familiar storage protocol locally while keeping the data in AWS. It
exists for the applications that cannot be changed to speak S3.

Four flavours. **S3 File Gateway** presents NFS and SMB, and each file becomes an S3 object --
which means lifecycle rules, replication and Glacier then apply to it like any other object.
**FSx File Gateway** does the same for FSx for Windows, with a local cache for branch offices.
**Volume Gateway** presents iSCSI block devices, either *cached* (primary data in S3, hot blocks
local) or *stored* (primary data local, asynchronously backed up to S3 as EBS snapshots). **Tape
Gateway** presents a virtual tape library to existing backup software -- Veeam, NetBackup,
Commvault -- and writes the tapes to S3 and Glacier, which is how a tape process is retired
without replacing the backup software.

Every flavour keeps a **local cache** so recently used data is served at LAN speed, and the
bandwidth to AWS is what limits everything else -- which is why it is usually paired with Direct
Connect.

In the exam it is the answer to hybrid storage phrased as "keep the on-premises application and
protocol unchanged, but store the data in AWS". It is distinct from **DataSync**, which is a
one-time or scheduled *transfer* rather than a standing presence, and from **Direct Connect**,
which is the pipe rather than the appliance.
