Neptune is a managed graph database on the Aurora-style storage layer, supporting both property
graphs (Gremlin, openCypher) and RDF (SPARQL).

Reach for it when the **relationships are the data** and the queries traverse them. Fraud
detection following rings of shared attributes; recommendations over "people who bought this
also bought"; identity resolution across accounts; network and infrastructure topology; and
knowledge graphs. The test is whether queries are multi-hop: *"find accounts within three
degrees of this one that share a device"* is a self-join three times deep in SQL and a single
traversal in Gremlin, and the gap widens with depth.

Everything else should not be here. A lookup by key is DynamoDB. Aggregates over rows are
Redshift or Athena. Full-text search is OpenSearch. Graph databases are slower and more
expensive than any of them at the jobs those are built for.

Features worth knowing by name: **Neptune Analytics** for running graph algorithms (centrality,
community detection, shortest path) over a loaded graph; **vector similarity search**, which
pairs it with retrieval-augmented generation when the retrieval should follow relationships as
well as embeddings; and bulk loading from S3, which is how a real graph gets in -- loading
hundreds of millions of edges through the query API is not practical.
