ValidatingAdmissionPolicy moves policy into the API server. You write CEL expressions --
`object.spec.containers.all(c, has(c.resources.limits))` -- and the API server evaluates them
during admission. No webhook, no Deployment, no TLS certificate to rotate, no timeout, and no
possibility of a policy outage making the cluster unwritable.

**That last property is the reason it exists.** The standard failure story of policy engines is a
webhook with `failurePolicy: Fail` whose Pods are unschedulable, which rejects every matching
write -- including the write that would fix it. In-process evaluation has no such mode. For
rules that are just "this field must be set", that is a strictly better place to run them.

**The separation of policy and binding is genuinely useful.** The policy is the rule; the binding
says where and how hard. The same "resources must be set" policy can be bound as
`Deny` in production namespaces, `Warn` in staging and `Audit` everywhere else, and with
`paramKind` it can carry different thresholds per binding -- one policy object, many enforcement
levels, which is what makes a gradual rollout practical.

**CEL is deliberately limited.** Expressions are side-effect free and bounded in cost, with no
network access and no reading of other objects, so they cannot be slow or unpredictable. That
rules out "no two Ingresses may claim the same hostname", which needs a cluster lookup, and
anything requiring external data. The `authorizer` variable is the one escape: it lets a policy
ask whether the requesting user has a particular permission, which is how you write
"only someone who can do X may set field Y".

**It cannot mutate.** MutatingAdmissionPolicy is following the same path, and until it lands,
anything that needs to *change* an object -- inject defaults, pin digests, add a security context
-- is still a webhook. The practical arrangement for most clusters is Pod Security Admission for
the standard profiles, CEL policies for the cluster's own validation rules, and a policy engine
kept for mutation and generation.
