Pulling an image is the first thing that happens to a Pod on a node and the first thing that can
go wrong. The kubelet asks the runtime, the runtime talks to the registry, and anything in
between -- DNS, a proxy, credentials, a rate limit -- surfaces as `ImagePullBackOff` with the
real reason in `kubectl describe pod`. It is worth reading that message rather than guessing:
`manifest unknown` is a wrong tag, `unauthorized` is a missing or wrong pull secret,
`toomanyrequests` is Docker Hub's anonymous limit hit by a whole cluster sharing one IP.

**Tags are the problem and digests are the fix.** A tag is a mutable pointer, so `app:1.4.2`
can mean two different builds on two nodes depending on when each pulled and what the pull
policy was. With `IfNotPresent`, a node that already has the tag cached never checks again. The
discipline that removes the whole class of problem is deploying by digest --
`app@sha256:...` -- which your CI knows after it pushes, and which makes the manifest an exact
statement of what will run. It also makes signature verification meaningful, since a signature
covers a digest and not a name.

**`latest` deserves its reputation.** It flips the default pull policy to `Always`, so every Pod
start is a registry round trip and a registry outage becomes an inability to restart anything,
and it makes rollback impossible because there is no earlier reference to roll back to.

**Pull secrets are usually attached in the wrong place.** Putting `imagePullSecrets` on the
ServiceAccount rather than on each Pod means every workload in the namespace gets it, including
ones added later by someone who does not know the registry is private. For nodes in a cloud,
the better answer is an identity the node or the workload already has -- ECR via the instance
role, Artifact Registry via Workload Identity -- so no credential exists in the cluster at all.

At scale, a pull-through cache or a registry mirror configured in the runtime is what keeps
image pulls off the public internet, keeps scaling events fast, and keeps you out of rate
limits. Pre-pulling images onto node images is the other half for workloads that must start in
seconds.
