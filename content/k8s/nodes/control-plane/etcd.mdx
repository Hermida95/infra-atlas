etcd is a strongly consistent, replicated key-value store, and in Kubernetes it holds every
object there is. The API server serialises objects into keys under `/registry` and relies on
etcd's revisions for watches and optimistic concurrency. Nothing else in the cluster has a
database -- which is the reason Kubernetes behaves coherently, and the reason this one component
deserves disproportionate care.

**Quorum is the whole operational story.** Writes require a majority of members, so three
members survive one loss and five survive two. Lose quorum and the cluster becomes read-only
until it comes back; lose the data on a majority and the cluster is gone, with no way to
reconstruct it from running Pods. Members should sit in different failure domains, on low-latency
disks -- etcd is fsync-bound, and a slow disk shows up as API server latency, leader elections
and flapping nodes long before anyone suspects storage.

**Size and compaction matter more than people expect.** The default quota is a couple of
gigabytes; exceed it and etcd goes into a read-only alarm state, which looks like a cluster that
accepts no writes at all. Old revisions are compacted automatically, but compaction does not
return disk space -- `etcdctl defrag` does. Clusters that churn objects quickly (lots of Events,
lots of Jobs, a noisy operator) are the ones that hit this.

**Security has no middle ground here.** There is no RBAC between etcd and the objects: read
access to etcd is read access to every Secret, every ServiceAccount token, every ConfigMap.
So it listens only to the API server over mutual TLS, it is never on the pod network, and
encryption at rest is configured in the API server rather than in etcd. If an attacker reaches
etcd, nothing else in your hardening matters.

**Backups are the only real safety net.** `etcdctl snapshot save`, taken on a schedule, stored
off the cluster, and -- the part teams skip -- restored at least once into a throwaway cluster
so you know the procedure and the certificates work. A backup nobody has restored is a guess.
