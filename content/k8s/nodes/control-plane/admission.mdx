Admission control is the hook that makes Kubernetes governable. Authentication says who you are
and RBAC says what you may touch, but neither can say "no Pod may run as root" or "every
workload must declare an owner" -- those are statements about object content, and content is
what admission sees. It is also the only place that can modify an object on the way in, which is
how sidecars get injected and defaults get filled.

**Mutating runs before validating**, which is the only ordering you have to remember: a mutating
webhook that adds a sidecar runs first, so the validating policy that checks every container's
security context sees the sidecar too. Mutating webhooks are called in sequence (each sees the
previous one's patch), validating ones in parallel (any rejection is final).

**A webhook is a dependency of every write.** This is where clusters get bricked.
`failurePolicy: Fail` on a webhook whose service is unavailable rejects every matching request
-- and if the match rule is broad enough to include the webhook's own Deployment or the
kube-system namespace, there is no way to fix it from inside the cluster. The protections are
mechanical and non-negotiable: scope `rules` as narrowly as the policy allows, exclude
kube-system with a `namespaceSelector`, keep `timeoutSeconds` low, run the webhook with more
than one replica, and think hard before choosing `Fail` over `Ignore`.

**Prefer in-process policy where it fits.** ValidatingAdmissionPolicy evaluates CEL expressions
inside the API server, so a rule like "every Pod must set resource limits" has no service, no
certificate rotation and no availability story at all. The remaining reasons to run a webhook
are mutation, cross-object lookups and anything needing real logic -- which is still plenty, but
a lot less than it used to be.

`kubectl apply --dry-run=server` is the tool that makes all of this visible: it runs the full
chain without persisting, so you see the mutated object a policy engine will actually store, and
the rejection message before it lands in a pipeline.
