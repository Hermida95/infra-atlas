A Pod is a group of containers that share a network namespace, a set of volumes and a fate. It
exists because some things genuinely need to be co-located and co-scheduled -- a proxy in front
of an app, an agent reading its files -- and because a scheduling unit needs a single IP. On
Linux it is implemented as a sandbox (a `pause` container holding the namespaces) with your
containers joining it.

**You almost never write one.** A bare Pod is not restarted if its node dies, not replaced if
it is deleted, and not rolled when its image changes -- nothing is watching it. Deployments,
StatefulSets, DaemonSets and Jobs all exist to create Pods from a template and keep doing so.
The exceptions are debugging (`kubectl run --rm -it`) and a genuinely one-shot task.

**Pods are immutable in the ways that matter.** You cannot change the image, the resources or
almost any field of a running Pod -- the API rejects it. The workload controller handles this by
creating a new Pod and deleting the old one, which is why "updating" a Deployment means replacing
every Pod it owns. In-place resource resize is arriving but is still narrow. The practical
consequence: anything that must survive a Pod replacement belongs in a PersistentVolume or
outside the cluster, and anything with an identity that must survive belongs in a StatefulSet.

**Multi-container Pods have a narrow correct use.** Containers in one Pod scale together, are
scheduled together, and fail together -- so two services with different scaling needs do not
belong in one Pod, however convenient the localhost call looks. The legitimate patterns are the
sidecar (proxy, log shipper, secret refresher), the adapter and the ambassador, all of which are
infrastructure attached to one app rather than another app.

**Terminating a Pod is a sequence worth knowing**, because getting it wrong is the cause of
dropped requests during every deploy: the Pod is marked for deletion, removed from endpoints,
sent `SIGTERM`, given `terminationGracePeriodSeconds` to finish, then `SIGKILL`. Endpoint removal
and SIGTERM race, which is why a `preStop` sleep is the standard mitigation.
