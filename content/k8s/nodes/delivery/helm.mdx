Helm renders a directory of Go templates with a values file into Kubernetes manifests, applies
them, and records the result as a release -- stored as a Secret in the namespace, one per
revision. That record is what makes `helm rollback` and `helm history` possible, and it is also
state in the cluster that can disagree with your repository.

**It won distribution.** Practically every piece of third-party software for Kubernetes ships as a
chart, so knowing how to read `values.yaml`, override it properly and inspect the result is a
basic skill. `helm template` renders without installing and is what you should look at before
applying anything; `helm diff` (a plugin) shows what an upgrade would change, which is the single
most valuable addition to the tool.

**Templating YAML as text is its fundamental weakness.** Indentation bugs, `nindent` mistakes and
a value that was supposed to be a string becoming a number are all normal, and the error surfaces
as invalid YAML or as a field silently in the wrong place. Charts that handle every possible
option grow into templates nobody can read. This is the trade against Kustomize, which
manipulates structured YAML and cannot produce syntactic nonsense -- at the cost of being far
less expressive.

**CRDs are the known sharp edge.** CRDs placed in a chart's `crds/` directory are installed on
first install and then never upgraded or deleted by Helm. So a chart upgrade that ships a new CRD
version does not apply it, and your new resources fail validation against the old schema. The
workarounds are applying CRDs separately in your pipeline, or using a chart that puts them in
templates and accepts the risk. Either way it has to be a conscious decision.

**For your own applications, the question is whether you need templating at all.** One chart with
values per environment is a real pattern; so is Kustomize overlays with no templating; so is
rendering with Helm and committing the output for a GitOps controller to apply. The worst of the
three is a chart so parameterised that reading it tells you nothing about what will be deployed.
